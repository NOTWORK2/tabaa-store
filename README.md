# متجر «طبعة» — ملابس بطباعة حسب الطلب

متجر عربي (RTL) يختار فيه الزبون القطعة واللون والمقاس والتصميم ويرى المعاينة قبل الطلب، مع لوحة إدارة للمدير والموظفين. كل الأسعار بالدرهم الإماراتي.

لا توجد قاعدة بيانات: البيانات ملفات JSON والصور والصوت ملفات عادية، وكلها داخل مجلد `data`.

## التشغيل

يتطلب Node.js 22 أو أحدث.

```powershell
npm install
```

```powershell
npm run build
```

```powershell
npm start
```

- المتجر: http://localhost:3000
- لوحة الإدارة: http://localhost:3000/admin
- لتغيير المنفذ: `node server/index.js --port 8080`

عند أول تشغيل يُنشأ حساب المدير `admin` بكلمة مرور عشوائية تُكتب في `data/admin-login.txt`. غيّرها من القائمة الجانبية «تغيير كلمة المرور» ثم احذف الملف.

يطبع الخادم عند التشغيل عنوانًا لفتح المتجر من الهاتف على نفس شبكة الواي فاي.

بعد بناء الواجهة، شغّل العرض المحلي بالأمر `npm run demo`. عند أول تشغيل ينشئ حساب العرض باسم `admin` وكلمة مرور `admin`، ويحفظ بياناته في `data/demo`. للتشغيل العادي استخدم `npm start`.

## أول ما تضبطه

1. أدخل رقم واتساب المتجر بالصيغة الدولية في **إعدادات المتجر** (`/admin/settings`) حتى يفتح زر تأكيد الطلب محادثة المتجر برسالة جاهزة. إذا تركت الرقم فارغًا، يختار الزبون المحادثة بنفسه في واتساب.
2. **المنتجات**: يعرض الكتالوج صورًا توضيحية واقعية مولّدة للقطع. يمكنك رفع صور بضاعتك وضبط مساحة الطباعة لكل منتج. تحتوي «مجموعة الأسماء» على ملفات طباعة شفافة، ويمكن تعديل أسعارها من قسم التصاميم.
3. **الموظفون**: أنشئ حسابًا لكل موظف بصلاحياته.

## أين تُحفظ البيانات

| المسار | المحتوى |
| --- | --- |
| `data/db/*.json` | الأنواع، المنتجات والمخزون، التصاميم، الطلبات، العملاء، المصاريف، الموظفون، الإعدادات |
| `data/storage/public` | صور القطع والتصاميم المعروضة، معاينات الطلبات، الشعار، الملف الصوتي |
| `data/storage/private` | ملفات الطباعة الأصلية (تُنزَّل من صفحة الطلب فقط بعد تسجيل الدخول) |

**النسخ الاحتياطي:** انسخ مجلد `data` كاملًا. لنقل المتجر إلى خادم آخر انسخ المشروع ومعه `data`.

كل طلب يحتفظ بنسخته الخاصة من السعر والتكلفة وصورة المعاينة وملف الطباعة، فلا يتأثر بتعديل المنتج أو التصميم أو حذفهما لاحقًا.

## حدود هذا التخزين

- الخادم يحمّل الملفات في الذاكرة ويكتبها عند كل تعديل، وهذا مناسب لمتجر صغير أو متوسط (آلاف الطلبات). شغّل **نسخة واحدة** فقط من الخادم على مجلد `data` نفسه.
- لا يوجد دفع إلكتروني: الزبون يختار طريقة الدفع (نقدًا أو بطاقة عند الاستلام أو تحويل) والموظف يسجّل التحصيل من صفحة الطلب.
- عند النشر على الإنترنت ضع الخادم خلف HTTPS (مثل Caddy أو Nginx).

## بنية المشروع

- `server/` — خادم Express: `store.js` (التخزين بالملفات)، `auth.js` (الجلسات والصلاحيات)، `routes/public.js` (المتجر)، `routes/admin.js` (اللوحة)، `lib/orders.js` (الطلبات، رسالة واتساب، حساب الأرباح).
- `web/src/store/` — واجهة الزبون. `web/src/admin/` — لوحة الإدارة.
- للتطوير: `npm run dev:api` و `npm run dev:web` في نافذتين (الواجهة على المنفذ 5173).

## النسخة الثابتة على GitHub Pages

الرابط: https://notwork2.github.io/tabaa/ (مستودع النشر العام `NOTWORK2/tabaa`، والكود المصدري يبقى في المستودع الخاص).

هذه النسخة واجهة الزبون فقط: التصفح والتخصيص والمعاينة والسلة تعمل من لقطة للكتالوج، والطلب يُرسل إلى المتجر عبر واتساب ولا يُحفظ في لوحة الإدارة. لا تحتوي لوحة الإدارة، ولا ينقص فيها المخزون.

لتحديث الموقع المنشور بعد تعديل المنتجات أو الأسعار أو رقم واتساب من لوحة الإدارة المحلية:

```powershell
npm run pages:deploy
```

للبناء دون نشر: `npm run pages:build` (الناتج في `web/dist-pages`).

## نشر المتجر الكامل على الإنترنت (Render)

هذا ينشر الواجهة ولوحة الإدارة معًا على خادم Node، فيصير للوحة رابط يُفتح من أي جهاز.

1. افتح https://render.com/deploy?repo=https://github.com/NOTWORK2/tabaa-store وسجّل الدخول بحساب GitHub.
2. وافق على الإعداد المقروء من `render.yaml` واضغط Apply، وانتظر انتهاء البناء.
3. رابط المتجر يظهر أعلى صفحة الخدمة (ينتهي بـ `.onrender.com`)، ولوحة الإدارة على `/admin`.
4. اسم المستخدم `admin`، وكلمة المرور هي قيمة `ADMIN_PASSWORD` في تبويب Environment للخدمة.

**الخطة المجانية لا تحفظ البيانات:** تُمسح الطلبات والمنتجات المضافة والصور المرفوعة عند كل إعادة تشغيل، وتتوقف الخدمة بعد 15 دقيقة بلا زوار ثم تعود ببياناتها الأولية (أول فتح بعد التوقف بطيء). تصلح للتجربة والعرض فقط. للمتجر الحقيقي فعّل القرص الدائم المشروح في آخر `render.yaml` (يتطلب خطة مدفوعة) مع `DATA_DIR=/var/data`.

أي استضافة Node أخرى تعمل بالطريقة نفسها: أمر البناء `npm ci --include=dev && npm run build`، أمر التشغيل `npm start`، والمتغيرات `PORT` و`DATA_DIR` و`ADMIN_PASSWORD` (10 أحرف على الأقل) و`TRUST_PROXY=1`.
